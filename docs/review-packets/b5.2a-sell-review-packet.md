# Review Packet — B.5.2A SELL Transaction Validation

*Self-contained for an external reviewer without repository access.*

---

## 1. What this system is

"Personal Stock Playbook" — a deterministic (non-AI) investment decision engine for a single personal portfolio. Given a position's current numbers and a written strategy, a pure-function "Decision Engine" computes concentration state, hard-constraint checks, an investment stance, action-zone eligibility, a scorecard, and two (currently unreconciled) trim-sizing models. This packet validates one thing: **does a real SELL transaction propagate correctly through the entire pipeline**, not just in isolation.

## 2. Relevant prior context

- **B.5.1** validated the static baseline (no transaction) and found the engine's trim-sizing math used an outdated, single-tier formula — reclassified after review as a model-design question, not a bug.
- The **B.5.1 Resolution** (completed before this test) added: (a) a fix making `portfolioTotalEur` stay flat on both BUY and SELL (Portfolio Total = Securities + Cash — selling converts stock value to cash, doesn't delete it), and (b) a new, generic **Target Position & Sizing Model** (`targetPosition` in engine output) that classifies a position as UNDERWEIGHT/WITHIN_TARGET/OVERWEIGHT relative to a target weight range, and reports three capacity tiers (minimum/preferred/maximumNormal) for trimming or adding — explicitly a *capacity* boundary, not a trade recommendation.
- This packet (B.5.2A) is the first test that exercises a **real transaction** (not a static snapshot) through the whole system, to confirm those fixes actually hold end-to-end.

## 3. Exact scenario

```
Pre-transaction (Unity baseline):
  shares = 902, avgCost = €27.76, price = €40.46
  portfolioTotal = €62,280
  strategy: targetWeightRange = 40–45%, shortTermCeiling = 50%, coreRange = 600–650 shares
  thesis = INTACT

Transaction: SELL 100 shares @ €40.46 (market price, no discount/premium)

Held constant: price, thesis, fundamentals, valuation, momentum.
```

## 4. Formulas / rules involved

```
applySell (weighted-average accounting):
  newShares = oldShares - soldShares
  newAvgCost = oldAvgCost  (unchanged — not tax-lot accounting)
  newValue = newShares × price
  realizedGain = (sellPrice - oldAvgCost) × soldShares

Portfolio total (cash-inclusive convention, fixed 2026-09-08):
  newPortfolioTotal = oldPortfolioTotal   (SELL proceeds become cash, stay in the tracked total)

Concentration state:
  ratio = weight / targetMax; thresholds at ×1.15 (moderate) and ×1.30 (severe)

Stance matrix (relevant branches):
  SEVERELY_OVERWEIGHT -> HOLD_GRADUALLY_TRIM
  OVERWEIGHT           -> HOLD_TRIM

HC-001: weight > shortTermCeiling (50%) -> accumulation disabled
HC-003 (checked separately, not part of engine output): would the sell drop shares below the 600-share core minimum?

Target Position capacity tiers (new model):
  weightShareRange = [ceil(total×0.40/price), floor(total×0.45/price)]
  feasibleStrategyRange = intersect(weightShareRange, coreRange)
  minimumTrim = currentShares - weightShareRange.max
  preferredTrim = currentShares - clamp(currentShares, feasible.min, feasible.max)
  maximumNormalTrim = currentShares - feasibleStrategyRange.min
```

## 7. Expected vs. actual

Every stated expectation (shares drop, total preserved, weight drops materially, tactical inventory and all three capacity tiers drop, thesis unchanged, ADD stays blocked because HC-001 hasn't cleared, core preserved) **matched exactly**. Stance was *not* pre-assumed — `HOLD_TRIM` is simply what the existing, already-approved stance matrix produces for OVERWEIGHT + non-weakening thesis, reported as observed rather than forced.

## 10. Assumptions / uncertainties

- The sell price equals the "current market price" input exactly (no slippage/discount modeled) — this is why `realizedGainPct` and `unrealizedReturnPct` come out numerically identical (both derived from the same price-vs-avgCost formula). Not a bug, just a property of this specific scenario; a sell at a different price would decouple them.
- `targetPosition.positionSizingState` stayed "OVERWEIGHT" through this transaction (both 58.6% and 52.1% exceed the 45% target ceiling) — this model has no severity tiers, unlike `concentration.state`'s four. This is expected given the model's design, not a defect, but worth watching in later concentration-boundary tests.

## 11. Bug vs. model-design distinction

No new findings from this scenario. One standing item, already classified in the B.5.1 Resolution closeout, reappears with new numbers rather than being newly discovered: `concentration.trimSizing.maxTacticalTrim` continues to numerically equal `targetPosition.trimCapacity.preferred` (152 = 152, same coincidence as 252 = 252 pre-transaction) because Unity's core ceiling remains the tighter upper constraint. This is a **model-design question** (should the old staging model be reconciled to consume the new capacity tiers?), not an implementation bug — and it was not re-litigated or newly reclassified here.
