# Review Packet — B.5.4B Core Protection under Thesis Deterioration

*Self-contained for an external reviewer without repository access.*

---

## 1. What this system is

"Personal Stock Playbook" — a deterministic (non-AI) investment decision engine for a single personal portfolio. B.5.4A validated HC-003 (a hard rule blocking a SELL that would breach a configured long-term core-share minimum) under a *healthy* thesis and resolved a cross-layer capacity question. This packet (B.5.4B) tests the same rule under **deteriorating** thesis — HC-003 currently treats WEAKENING and BROKEN identically, waiving core protection entirely for both. The goal is to validate current behavior and surface whether that grouping produces coherent semantics — not to change it.

## 2. Relevant prior context

- **HC-003**: `triggered = (remainingShares < coreMin) && thesisHealth NOT IN [WEAKENING, BROKEN]`. Deteriorating thesis disables this hard constraint entirely.
- **B.5.4A** established `targetPosition.maximumNormalTrim` as a "normal, healthy-thesis" strategic capacity figure, explicitly documented as applying "only while the thesis is healthy" — but that precondition lives only in prose, not in the return value itself.
- **HC-002** (accumulation-disabling constraint) is scoped to `thesisHealth === "BROKEN"` only — it does not treat WEAKENING as deterioration.
- **Stance** (`deriveStance`) treats BROKEN as an unconditional override (→ `THESIS_REVIEW`), but treats WEAKENING conditionally — it only escalates to `REDUCE_RISK` when *also* paired with an overweight concentration state.

## 3. Exact scenario

```
Strategy (unchanged): core 600-650, target weight 40-45%, price €40.46, portfolioTotal €62,280
Starting position: 650 shares
Proposed transaction: SELL 100 -> remaining 550
  (breaches the 600-share core floor AND the 616-share weight-target floor
   AND exceeds maximumNormalTrim's own 34-share "normal" boundary)

Run under thesis: A. INTACT   B. WEAKENING   C. BROKEN
```

## 6. Two findings

**Finding 1 — the `THESIS_REVIEW` action zone cannot reflect actual thesis health.** Even when thesis is BROKEN and `stance` has already escalated to `"THESIS_REVIEW"`, the `THESIS_REVIEW` action zone's own `state` field still reads `"CONDITIONAL"` — identical to the INTACT case. Confirmed in code: the function that derives every action zone's state does not accept a thesis parameter at all:

```ts
export function deriveActionZoneState(
  type: ActionZoneType,
  concentrationState: ConcentrationState,
  accumulationEnabled: boolean   // no thesisHealth parameter
): ActionZoneState {
  ...
  case "THESIS_REVIEW":
    return "CONDITIONAL"; // thesis-driven only — not weight-driven (comment, not enforced)
}
```
The comment claims "thesis-driven," but nothing in the function's signature or body is actually driven by thesis. This is not a coding error relative to what's written — it faithfully implements exactly what the switch statement says — but it means the UI has no structural way to visually distinguish "thesis fine" from "thesis broken" for this specific zone.

**Finding 2 — `maximumNormalTrim` doesn't signal when its own precondition no longer holds.** `targetPosition` never takes a thesis input, so `maximumNormalTrim` = 34 in all three cases (this independence is *correct and intentional* — capacity shouldn't silently change with thesis unless explicitly designed to). But the model's own documentation says this figure applies "only while the thesis is healthy." Under WEAKENING/BROKEN, HC-003 permits selling all the way to 550 — far past 34 — with nothing in `targetPosition`'s output indicating that its "normal capacity" framing no longer describes the operative constraint. A caller reading only `targetPosition` in isolation would see "34" with no signal that thesis has already made that number moot.

## 7. Expected vs. actual

Every HC-003 expectation matched exactly. No forcing was required, no deviation found.

| Item | Classification |
|---|---|

| `THESIS_REVIEW` zone always CONDITIONAL, even under BROKEN | **FAIL — RULE / MODEL DESIGN QUESTION** |

No implementation bugs. Two design questions, neither resolved.

## 9. Test results

New test file (8 tests, 4 groups) exercises the real `checkHC003()` across all three thesis states and the real `runDecisionEngine()` at the same starting position, confirming both findings directly rather than by inspection alone. Full suite: 90/90 passing. Type check, lint, build all clean.

## 10. Bug vs. rule/model-design distinction

No implementation bugs — every observed behavior matches what the current code, as written, actually specifies. Both findings are about whether that specification is *coherent*, not whether the code correctly implements it.

## 11. Assumptions / uncertainties

- This packet used a starting position that is `WITHIN_TARGET` by weight (650 shares ≈ 42.2%) — a different starting concentration (e.g. overweight) would exercise `deriveStance`'s `WEAKENING + overweight → REDUCE_RISK` branch, which was not tested here.
- HC-002's BROKEN-only scope and stance's WEAKENING-needs-overweight-to-escalate rule are both *existing, already-approved* behaviors — reported as context for Finding 1/2, not flagged as new problems themselves.

## 12. Open questions for the reviewer

1. Should the `THESIS_REVIEW` action zone eventually take thesis health as an input and distinguish, e.g., "dormant" vs. "active" states — or is a single always-CONDITIONAL state intentional (perhaps because the UI derives its own thesis-review prompt from `stance` directly, making the zone's own state redundant)?
2. Should `targetPosition` (or a wrapping layer) surface some flag when its "normal capacity" assumption (healthy thesis) is known to be violated, rather than silently returning the same number?
3. Is HC-003's binary WEAKENING/BROKEN grouping — coarser than the rest of the engine's treatment of the two states — worth tightening, or is "core protection is an all-or-nothing hard rule, thesis nuance belongs elsewhere" the correct framing?
