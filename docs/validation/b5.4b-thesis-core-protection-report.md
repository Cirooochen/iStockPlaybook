# B.5.4B — Core Protection under Thesis Deterioration

Status: PASS (resolved 2026-09-09 — see *Resolution* below; original
review-required findings preserved unchanged)

Scope: validates CURRENT behavior only. See `docs/VALIDATION_PROTOCOL.md`
for method/format; `docs/playbook-decision-engine-spec-v0.1.md` §21A for
the target-position model this checkpoint exercises, and §16 for the
resolved HC-003 rule.

Method: real `checkHC003()` and real `runDecisionEngine()`, same
scenario, three `thesisHealth` values. Test file (pre-existing, still
exact-match for this scenario, no duplication added):
`src/domain/validation/b5.4b-thesis-core-protection.test.ts` (8 tests).

## Scenarios

Unity strategy fixed: core 600–650, target weight 40–45%, price €40.46,
portfolio total €62,280. Starting position **650 shares**, proposed
**SELL 100 → remaining 550** (breaches core min 600, weight-implied min
616, and `maximumNormalTrim`'s own 34-share boundary, all at once). Run
under thesis **INTACT / WEAKENING / BROKEN**.

## Findings (original pass — pre-resolution, preserved as-is)

1. **PASS (superseded — see *Resolution*)** — at the time of this
   finding, HC-003 treated WEAKENING and BROKEN identically (both waived
   core protection); INTACT did not. Matches the implementation as it
   stood at that time.
2. **PASS** — `targetPosition` (incl. `maximumNormalTrim`) is
   structurally thesis-independent (`deriveTargetPosition`'s input type
   has no thesis field) — confirmed, not incidental. Correct: strategic
   capacity should not silently change with thesis health.
3. **RULE / MODEL DESIGN QUESTION (RESOLVED — see *Resolution*)** —
   HC-003's binary "WEAKENING or BROKEN ⇒ deteriorating" grouping was
   coarser than the rest of the engine: HC-002 is BROKEN-only, and
   stance only escalates unconditionally for BROKEN (WEAKENING needs
   accompanying overweight concentration to matter). So although HC-003
   waived core protection identically for both, the surrounding engine
   treated WEAKENING and BROKEN as materially different severities.
4. **RULE / MODEL DESIGN QUESTION** — cross-layer signaling gap (same
   root cause as the B.5.4A-resolved core-vs-weight-floor distinction,
   see `docs/validation/b5.4a-core-protection-report.md` §7a, not
   reopened here): once thesis deteriorates, HC-003 permits a sell well
   past `maximumNormalTrim` (34), but `targetPosition`'s output carries
   no signal that its own "healthy-thesis" precondition is no longer
   met — a caller reading `targetPosition` alone would not know 34 has
   stopped being the operative ceiling.
5. **Observation, not a new finding** — `actionZones.THESIS_REVIEW`
   stays `CONDITIONAL` in all three states, including BROKEN with
   stance already at `THESIS_REVIEW` (`deriveActionZoneState` takes no
   thesis parameter). Carried forward from the prior B.5.4B pass; not
   re-litigated as new evidence here.

No implementation bugs.

## Resolution (2026-09-09) — approved rule change

**Decision:** HC-003 must distinguish WEAKENING from BROKEN.

```text
INTACT     → core protection active
WEAKENING  → core protection remains active (thesis is under concern,
             but the long-term core commitment has not yet been
             invalidated)
BROKEN     → core protection removed (the thesis supporting the
             long-term core is no longer valid)
```

**Implementation:** `checkHC003` (`src/domain/playbook/hard-constraints.ts`)
now waives core protection only when `thesisHealth === "BROKEN"`
(previously: `WEAKENING or BROKEN`). Spec §16 updated with the same
rule and cross-referenced to this report.

**Re-validated (same scenario — 650 shares, sell 100, remaining 550):**

| | INTACT | WEAKENING | BROKEN |
|---|---|---|---|
| HC-003 `triggered` | true (blocked) | **true (blocked)** | false (allowed) |
| `targetPosition.trimCapacity.maximumNormal` | 34 | 34 | 34 |
| `stance` | HOLD | HOLD | THESIS_REVIEW |
| `actionZones.ADD` | ACTIVE | ACTIVE | INACTIVE |

Only the WEAKENING column changes (`triggered`: false → true); all
other outputs are unaffected, confirmed via the real `checkHC003()` and
real `runDecisionEngine()`.

**maximumNormalTrim / targetPosition:** not redesigned, per instruction.
Remains the NORMAL strategic-capacity boundary and does not become
thesis-sensitive. The cross-layer signaling gap from Finding 4 —
`targetPosition` carries no signal when HC-003 permits a sell past
`maximumNormalTrim` under BROKEN — is explicitly deferred, not resolved
by this change (tracked in spec §21A and protocol §8 alongside the
existing deferred issues list). No risk-reduction/exit capacity
introduced.
