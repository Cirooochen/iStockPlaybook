# B.5.5 — Thesis Validation

Status: PASS / COMPLETE

Scope: implements and validates the spec §22 ADD thesis-eligibility
clause (v0.1 decision, 2026-09-09). See `docs/VALIDATION_PROTOCOL.md`
for method/format; `docs/playbook-decision-engine-spec-v0.1.md` §16
(HC-002/HC-003), §18 (stance), §22 (Add Logic) for the rules exercised
here.

## v0.1 decision implemented

```text
ADD thesis-eligible:    STRENGTHENING, INTACT
ADD thesis-ineligible:  MIXED, WEAKENING, BROKEN
```

MIXED and WEAKENING deliberately share this outcome for v0.1 — no new
stance/HC behavior was added to separate them. Their semantic
distinction remains in `ThesisHealth`/`scorecard.thesisHealth` and is
expected to matter more once Phase C/D evidence and fundamental logic
land. BROKEN remains structurally different: it is additionally
ADD-ineligible via HC-002 (`accumulationEnabled = false`), and is the
only state where HC-003 core protection is removed.

## Implementation

- `src/domain/thesis/thesis.ts` — added `isThesisEligibleForAdd(health)`,
  the single source of truth for the §22 thesis clause.
- `src/domain/playbook/action-zones.ts` — `deriveActionZoneState`'s
  third parameter is now `AddEligibility { accumulationEnabled,
  thesisEligible }` instead of a bare boolean. The ADD case ANDs both
  gates before falling through to the existing concentration-state
  logic. `AddEligibility` is intentionally structured to take additional
  gates (fundamentals/valuation) in Phase C without restructuring the
  function — no other zone type reads it.
- `src/domain/engine.ts` — computes `thesisEligible:
  isThesisEligibleForAdd(thesisHealth)` alongside the existing
  `accumulationEnabled` and passes both as `addEligibility` to
  `deriveActionZoneState`.

No changes to HC-001/HC-002/HC-003, stance rules, or any other action
zone. No fundamentals/valuation score gating added (Phase C, still not
implemented — genuinely deferred, not part of this decision).

## Findings

**PASS.** The five-state ADD ladder matches the approved v0.1 decision
exactly: STRENGTHENING/INTACT → ACTIVE (thesis-eligible, accumulation
enabled); MIXED/WEAKENING → INACTIVE (thesis-ineligible, though
accumulation stays enabled); BROKEN → INACTIVE (both gates fail).
HOLD/TRIM_1/TRIM_2/THESIS_REVIEW remain identical across all five
states — only ADD reads `thesisEligible`, as intended.

Carried forward, not reopened:

1. WEAKENING remains functionally equivalent to INTACT/STRENGTHENING in
   HC-002, HC-003, and stance at this fixed WITHIN_TARGET concentration
   (unchanged by this decision — `deriveStance`'s WEAKENING-escalation
   branch is conditional on overweight, approved in B.5.4B).
2. `actionZones.THESIS_REVIEW` stays `CONDITIONAL` for all five states,
   including BROKEN (`deriveActionZoneState` takes no thesis input for
   this zone type — see B.5.4B). Not touched by this decision; spec §23
   still describes a triggering condition this zone's `state` field
   cannot structurally express.
3. The `fundamental_score >= 60`/`valuation_score >= 60` clauses of
   spec §22 remain NOT YET IMPLEMENTED — Phase C scope, no real
   fundamentals/valuation formulas exist yet. `AddEligibility` is
   structured so these can be added as further gates later without
   revisiting this checkpoint's design.

No implementation bugs.
