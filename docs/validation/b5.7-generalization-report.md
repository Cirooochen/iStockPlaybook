## Findings

1. **PASS — no hidden Unity-specific numbers in domain/rule logic
   (Q1).** `engine.ts`, `concentration.ts`, `target-position.ts`,
   `hard-constraints.ts`, `stance-rules.ts`, `action-zones.ts`,
   `scoring.ts`, `thesis.ts`, `signals.ts`, and `ruleset-v0.1.ts`
   contain none of Unity's specific position figures (902 shares,
   €27.76 average cost, €40.46 execution price) — checked directly via
   source inspection, not inferred. One harmless, purely cosmetic
   exception: `target-position.ts`'s type doc comments use "e.g. 58.6"
   and "e.g. 45" as illustrative examples that happen to reuse Unity's
   historical numbers — comment-only, zero functional effect, not a
   generalization defect. Not changed here (out of scope: a doc-comment
   wording tweak, not a validation finding requiring code change).

2. **PASS — the model works for all four required cases (Q2).**
   Zero position (A: 0 shares, UNDERWEIGHT, no crash or misclassification
   — `addCapacity`/`trimCapacity` both computed correctly with `averageCostEur:
   0`), underweight accumulation (A and B both produce `ADD = ACTIVE`
   with correct capacity math), overweight reduction (C: OVERWEIGHT,
   `ADD = INACTIVE`, `TRIM_1 = WATCH`, correct trim capacity), and both
   strategy shapes — weight-only (A, B: `strategyAlignment =
   NOT_APPLICABLE`, feasible range defaults to the weight range) and
   with-core (C: `strategyAlignment = ALIGNED`, feasible range is the
   intersection) — all through the unmodified real engine.

3. **PASS — concentration thresholds are strategy-derived, not
   Unity's (Q3).** `classifyConcentration` used each strategy's own
   `mediumTermTargetMaxPct` (12% / 8% / 25%) with the same generic
   `RULESET.concentration` multipliers (1.15/1.30) throughout — Gamma
   Semi's 30% weight correctly classified OVERWEIGHT relative to *its*
   25% target max, not Unity's 45%. Separately confirmed HC-001 and
   concentration-OVERWEIGHT are genuinely independent, strategy-specific
   knobs: Gamma Semi's 35% short-term ceiling is decoupled from its 25%
   target max, so `hc001.triggered = false` even while OVERWEIGHT —
   unlike Unity's configuration, where the two thresholds happen to
   always co-occur (a numeric coincidence of Unity's specific config,
   already flagged in the B.5.6 report, now confirmed to be exactly
   that — a coincidence, not a hidden general rule).

4. **PASS — `preferredTargetWeightPct` works generically (Q4).**
   Beta Corp's explicit `preferredTargetWeightPct: 6` at a completely
   different price/portfolio scale (€120/€200,000 vs. Unity's
   €40.46/€62,280) correctly resolved to 100 shares
   (`round(200000 × 0.06 / 120)`), landing inside `weightShareRange`
   with no clamping needed — matches the already-approved formula from
   `resolvePreferredTargetShares`, exercised end-to-end through the real
   engine for the first time (previously only unit-tested directly
   against `deriveTargetPosition`, never via `runDecisionEngine`).

5. **PASS — nothing prevents reuse for a second, normal stock (Q5).**
   All three synthetic strategies ran the complete, unmodified pipeline
   (Position → Concentration → Target Position → Hard Constraints →
   Thesis → Stance → Action Zones) end-to-end and produced internally
   consistent, spec-aligned output every time, with zero special-casing,
   errors, or `NaN`s. This is also the first checkpoint to exercise
   `runDecisionEngine()` with anything other than Unity's seed data —
   every prior B.5 checkpoint (B.5.1–B.5.6) used `unitySeed`/
   `unityScorecard`/`unityActionZones` exclusively.

Carried-forward observations, not new findings, reconfirmed to be
generic (not Unity-specific) rather than fixed here:

- `deriveStance` never returns `ADD`/`BUILD`/`EXIT` — `Stance`'s full
  union is declared but only `HOLD`/`HOLD_TRIM`/`HOLD_GRADUALLY_TRIM`/
  `REDUCE_RISK`/`THESIS_REVIEW` are ever produced (WITHIN_TARGET always
  falls through to `HOLD`, even for Strategy A's brand-new zero-share
  position). Matches `stance-rules.ts`'s own comment ("Phase C will
  refine with valuation/fundamentals signals") — a known, generic gap,
  not something Strategy A's zero-position case newly exposes.
- `concentration.state` has no `UNDERWEIGHT` value (`ConcentrationState`
  is `WITHIN_TARGET`/`MODERATELY_OVERWEIGHT`/`OVERWEIGHT`/
  `SEVERELY_OVERWEIGHT` only) while `targetPosition.positionSizingState`
  does distinguish `UNDERWEIGHT` — Strategies A and B both show this
  simultaneously (`concentration.state = WITHIN_TARGET`,
  `positionSizingState = UNDERWEIGHT`). This is the already-approved
  "two different layers, not equivalent" model from the B.5.1
  Resolution, now confirmed to hold generically, not as a Unity
  coincidence.

No implementation bugs. No rule/model design question surfaced that
requires a product decision — every result matched the existing,
already-approved rule set applied to new numbers.
